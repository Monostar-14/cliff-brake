# 悬崖急刹 (Cliff Brake)

[![CI](https://github.com/Monostar-14/cliff-brake/actions/workflows/ci.yml/badge.svg)](https://github.com/Monostar-14/cliff-brake/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

一个单页网页小游戏：车在有限长度的路上自动加速到 100 km/h，路尽头是悬崖。
把车在崖边刹停就赢，停得越贴边分越高；刹不住掉下去就输。

**在线试玩**（免下载）：<https://monostar-14.github.io/cliff-brake/>　｜　
3D 版：<https://monostar-14.github.io/cliff-brake/index-3d.html>

**本地玩**：双击 `index.html`，或双击 `悬崖急刹-单文件版.html`（单文件版可以直接发给别人）。
按住 <kbd>空格</kbd> 或按住底部红色按钮 = 踩刹车。浏览器直接跑，不需要服务器、不需要联网。

## 规则（一句话版）

> 一脚踩到底 = 必死。要**点刹**：踩住半秒多、松一下让力度表回落，反复点。

| 量 | 数值 | 说明 |
|---|---|---|
| 巡航速度 | 100 km/h | 加速到这个速度才解锁刹车按钮（速度 = 解锁门槛） |
| 刹车减速度 | 9.2 m/s² | 固定值（≈0.94g，真车感） |
| 够不够停 | 从 100 刹停需踩住 **3.02 s** | = v ÷ a |
| 理想刹停距离 | **41.9 m** | 一脚不松的最短距离 |
| 点刹刹停距离 | **≈59 m** | 0.6s 踩 / 0.3s 松的节奏（比一脚多滑 15~20 m） |
| 踏板力度累积 | **+564 N/s**（按住）/ **−204 N/s**（松开） | 力度表读数 |
| 断裂阈值 | **1612 N** | = 一脚不松 **2.86 s** |

关键就在 **2.86 < 3.02**：一脚踩到底，会在车停下前 0.16 秒（此时还剩约 5 km/h）把踏板踩断，
之后刹车彻底失效，车滚下悬崖。想活命只能点刹——松手期间力度回落、但车不减速，
所以点刹要比"一脚踩死"多滑 15~20 米（实测 59 m），**必须提前开始点刹**。

失败方式一共三种：① 刹车太晚 ② 全程不刹 ③ 一路死踩 / 乱松手把力度表顶到 1612 N。

**踏板一旦断裂 = 立刻判负**，不会让车"慢慢溜到崖边"让你干等：
① 抱死甩尾（地面，浓烟 + 火花 + 横向擦痕）→ ② 弹射飞出、空中翻滚（拖尾烟雾，镜头锁死）
→ ③ 砸回地面白闪尘爆（撞毁）或飞过崖边直坠峡谷。整段动画约 1.2~2.9 秒，然后结算。

## 计分

停在崖前 `margin` 米 → 得分 `100 − margin`（0~100 分）。
S ≥97 / A ≥90 / B ≥75 / C ≥40 / D 其他。历史最佳存在 localStorage。

## 3D 版说明

`index-3d.html` 是视角在**车右后方**（车后 8.6m、右侧 3.9m、高 3.4m）的第三人称追尾版本，
玩法/数值/失败判定和 2D 版完全一致（physics 共用同一份 `game.js`）。

渲染是**手写的软件三维渲染器**（`view3d.js`，约 700 行，零依赖、不联网、不用 WebGL/three.js）：

```
世界多边形 → 相机空间 → 近平面裁剪 → 透视投影 → 按"层 + 深度"排序 → 填充
（画家算法 + 方向光平面着色 + 距离雾）
```

- 相机：`lookAt(车头 - 8.6, 3.4, 3.9 → 车头 + 9.5, 1.0, 0)`，带平滑跟随；失控/坠落时锁定镜头
- 图层顺序：峡谷/远山 → 崖壁 → 台地 → 柏油路 → 标线 → 路边景物 → 车 → 尘烟 → 标签
- 车用长方体拼（车身/座舱/四轮/灯），失控动画走三维姿态：地面甩尾=绕 Y 偏航，
  弹射腾空=绕 Z 俯仰翻滚（`rotYaw` / `rotPitch`，由内核提供）
- 为什么不用 three.js：要保持"双击就能玩、能单文件发给别人、离线可用"，
  所以不引 CDN；自写渲染器足够画这个场景（约 780 个多边形/帧）
- 坑（都已踩过并修好）：多边形之间要 `stroke()` 同色补缝否则有发丝缝；描边色必须每个多边形重设，
  否则继承上一条线的颜色导致车身出现亮边；"宽度"要按真实米数给（1.8m 宽的白线会变成巨大色块）；
  贴脸的长条要按深度剔除；天空的太阳按方向投影（无限远），不按位置。

## 想改难度？

只改 `game.js` 顶部的 `CFG` 即可，`theoretical()` 会自动算出提示文案用的数值：

- `forceRamp` 调小 → 力度表涨得慢 → 能连续踩更久、更容易（但"点刹"戏码变弱）
- `brakeDecel` 调大 → 刹停更快更短，需要的踩踏时间更少
- `forceBreak` 就是 1612 N（题面定的）
- `roadLenMin/Max` 悬崖距离随机区间（现在 200~245 m）；`engineMin/Max` 本局发动机加速度随机区间
  （决定"到 100 km/h"的位置，也就是留给你的反应窗口有多长：现在 1.7~4.0 s）
- **改 `kmhCruise` 时记得同步缩放 `forceRamp`/`forceDecay`**：断裂时间必须短于刹停时间
  （`forceBreak/forceRamp < v₀/brakeDecel`），否则"一脚不松必断"失效、点刹机制作废。
  150→120→100 km/h 时系数按 `forceRamp = 5.64 × kmhCruise`、`forceDecay = 2.04 × kmhCruise` 走；
  路长按 v² 缩放（反应窗口的"秒数"才不变）。
- 改完跑 `python run-tests.py`（17 项物理断言 + 两版页面自检）和 `tune-mc.html`（胜率/评分分布）

## 一个设计上的硬约束（别踩坑）

最初的设想是"减速度正比于累积踏板力度"，那样在数学上**根本玩不了**：
让力度涨到 1612 N 所需的最小冲量是 `1612²/(2R)`，而把车从 100 km/h 刹停所需冲量是 `v₀/g`。
只要前者大于后者（正常参数下必然如此），车**永远先停下**、踏板永远来不及断——
"踏板会断"就是死代码；反过来如果让前者小于后者，则任何操作都刹不住车，游戏无解。
二者互斥，与参数无关。

所以这里改成：**减速度取固定值 9.2 m/s²**，踏板力度表只按"按住的累计时间"累积
（松手回落）——这正是"力度由按下刹车按钮的时间来计算"的字面实现，而且两种死法
（刹太晚 / 把踏板用断）都真实可达。
